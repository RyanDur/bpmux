Darcula design-system — forms grammar

Antlia's form-controls. The 4 form surfaces in bpmux are the same form in different clothes — this unifies them into one FIELD primitive + one ACTION primitive, composed into two archetypes. Spacing follows your proximity rule: tight WITHIN a purpose-group (label→field 4, button→button 8), a consistent looser distance BETWEEN groups (24). Mockup-first; rendered at real size.

1 · The FIELD primitive (every input is this)

A caption-label hugging its control (4px), one control style, and explicit STATES — the states today are ad-hoc per surface (the reject focus-ring exists; comments/chat have none; no error state anywhere).

2 · The ACTION primitive

The button hierarchy (from the button-primitive slice) + an 8px group gap; right-aligned in a modal, inline in a composer. Primary is the one default action; ghost dismisses; danger for destructive confirms.

button → button8 everywhere ✓--action-gap: 8 (keep)

What this gets you: the reject-modal, bug-dialog, comment box, and chat input all read as ONE family — same field, same buttons, same rhythm — learned once. The error + disabled states (missing today) come for free with the primitive. #1518's reject-modal is the first consumer (ships on current tokens now; re-skins onto this when Antlia lands).

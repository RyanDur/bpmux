2 · The unified status & signaling language (the coherence)

THE problem, grounded: "all-good" is ✓ in CI but ● in Sync; Sync sprawls to 9 glyphs (●○?◌⚠✗↻◔⊘) while CI uses 5 — three signals, three vocabularies. One canonical grammar fixes it: 5 semantic states, each ONE glyph + ONE colour (shape + colour both carry it → colourblind-safe), applied everywhere.

StateGlyphColourMeans
OK●successsynced · CI passing · online — all good
WORKING◌warningsyncing · CI running · recovering — in progress
ATTENTION◐warningoffline-queued · quota · stale · away — degraded, needs you, not failed
ERROR✗errorCI failed · drained-failure · startup-fail — broken
UNKNOWN○dimloading · unreachable — no data yet

Glyph logic: filled ● = present/good · hollow ○ = absent/unknown · ◌ = spinner/working · ◐ = half/degraded · ✗ = broken. Count-badge (the Sync pending count) rides any state as a small superscript.

4 · WCAG contrast audit (the palette is accessible by construction)

Every proposed pair computed against WCAG 2.1 (AA = 4.5:1 normal text · 3:1 large-text/UI/icons). The palette passes — with one correction the audit forced: --bg-highlighted darkened #4e5254 → #44474a so text on a selected row / textarea clears 4.5:1 (it was 4.11). Result:

pairrationeedverdict
fg-primary #bbbbbb on bg-base7.384.5PASS
fg-primary on bg-elevated5.534.5PASS
fg-primary on bg-highlighted #44474a4.874.5PASS (was 4.11 on #4e5254)
fg-secondary #a9b7c6 on base / elevated / highlighted6.93 / 5.19 / 4.584.5PASS
accents brand/ok/warn/err on base (as fill/border/icon)3.43–4.253.0PASS
primary-button text #0d1116 on brand-fill4.594.5PASS
focus-ring brand vs base3.433.0PASS

Usage-rules the audit pins (so colored-text never goes low-contrast — the #1 dark-theme a11y bug): fg-dim #808080 (3.59:1) and the accents as text (brand 3.43, err 3.56) are large-text / non-essential / UI-only — never small body copy. As fills, borders, icons, and large labels they pass; as 13px paragraph text they don't. The system encodes this: accents are fill/border tokens, body text is always fg-primary/secondary.

5 · Light mode — dual-theme (the IntelliJ-Light counterpart)

The system is DUAL-THEME (Ryan: "remember there is a light mode"). The Darcula dark palette pairs with an IntelliJ-Light counterpart; tokens swap via [data-theme="light"] (already in tokens.css), components stay theme-agnostic (they read tokens, never hard-coded colours), and the 5-state status grammar carries in both (shape + colour). Grounded in the live light tokens:

Light WCAG (same discipline as dark; exact ratios computed at synthesis): fg-primary/secondary/dim clear 4.5:1 on every surface (dark text on light bg). The SAME usage-rule as dark holds: fg-dimmer + accents-as-text (error/success) are large-text / UI-only (they don't clear 4.5:1 as small body copy); body text is always fg-primary/secondary, accents are fill/border. So the system is accessible-by-construction in BOTH modes — ONE usage-discipline, two palettes. 6 · Typography · motion · focus-ring (the rest of the foundation)

The cross-cutting tokens every component reads (grounded in styles/tokens.css + cross-cutting-research.md). Theme-agnostic — these don't change between dark/light.

Type scale (rem-based — respects user zoom)

tokensizeuse

rem for fonts (zoom-safe) · px for borders/hairlines · %/fr for responsive widths (css-canon unit-discipline). One scale; never an off-scale font-size.

Motion (GPU-friendly; honor prefers-reduced-motion)

tokenvalueuse
--motion-duration-instant80mshover/active feedback
--motion-duration-fast150mstoggles · focus-ring · small reveals
--motion-duration-medium250msopen/close · mount-in · drag-settle

+ the 3 ease tokens. Animate transform/opacity only (GPU); animations live in CSS (css-canon). --invisible-placeholder: 0.001 = the dragged-row treatment (kept in flow + a11y-tree).

Focus-ring (WCAG 2.4.7 — one token, every interactive element)

A single --focus-ring: 3px, ≥3:1 contrast vs adjacent (the brand accent in dark, the light-brand in light — both audited ≥3:1). Visible on EVERY interactive element at all times for keyboard users; standardized as a token so no surface invents its own (or omits it — the story-grip's missing ring, fixed in the list/row primitive). Target size ≥44×44 (invisible-padding ok).

What this gets you: wherever a status shows — the board-sync glyph, the CI glyph, a roster presence dot — it speaks the SAME 5-state language. You learn it once; ●=good, ◌=working, ◐=needs-you, ✗=broken, ○=unknown, everywhere. That's the coherence you asked about.

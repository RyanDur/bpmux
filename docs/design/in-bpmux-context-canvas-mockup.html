The model: each floating box is a two-way agent↔human CONVERSATION bound to a context (a design + the point/region it's pinned to). The box CARRIES that context → the agent is informed without anyone passing it (the flip-pain, solved). A new box opens wherever a new context begins; the main chat gets a deep-link ref (💬 →) so the team's aware + can jump. Coexists with chat, never replaces it. One-to-many participants (Ryan 2026-06-06): each box is participant-SCOPED like a bpmux channel — 1:1 (you + me), or pull in dev/pm for a multi-agent+human context (box #2 above pulls dev in) — reusing the existing DM/group/broadcast scoping; the box shows + lets you edit who's in it.

Thin-first slice (smallest real value): ONE design in the canvas + ONE anchored context-box (point-pin) where you + I converse, mirrored as a deep-link in the main chat. Validates the riskiest bit: an anchored conversation that carries its context end-to-end. North-star path: multiple boxes · new-box-on-new-context · region/object anchoring · resolve/collapse · infinite-canvas pan/zoom · live multiplayer.

Open design Qs to talk through: does a box's conversation ALSO live in the main chat-log (one stream, two views) or only on the canvas (deep-link in)? · when a context resolves, does its box collapse to a dot? · does the agent get auto-subscribed to a box when it's pinned to its work?
